# AGENTS.md

## Project aim

`@fang2hou/dsh-locale-ja` is a **standard DSH client plugin package** for
DeepSeek Harness (DSH) `0.1.0-rc.6`. It supports the `web` profile and browser
UI only. Keep the standard package shape:

- `src/index.ts` is the Host half and exports an empty `apply()` so
  `cordis.patch.yml` can mount the package's Loader row; it owns no Host
  behavior.
- `src/client/index.ts` is the browser half and assembly point. The package
  exposes it through `exports["./client"]` and declares `dsh.client` with
  `platform: "web"`, `immediately: true`, and `inject: ["@deepseek-ai/dsh-client-locale"]`.
- `package.json` declares `dsh.bundle.patch: "./cordis.patch.yml"` so
  `dsh plugin --profile web add @fang2hou/dsh-locale-ja` installs a profile
  bundle whose patch mounts the Loader row.
- `lib/` is generated output; never edit it by hand.

Read [ARCHITECTURE.md](./ARCHITECTURE.md) and the relevant
[ADRs](./docs/adr/) for the package boundaries and compatibility decisions.

## DSH plugin development rules

- Query the real runtime capability and contract before relying on a DSH
  Service, Event, Builtin, Slot, or internal field. Never infer an API from a
  name, type name, or example.
- Use `ctx.get()` with an absence check for optional Services. Use `inject` only
  for true hard dependencies that the plugin cannot operate without.
- Register UI only through the queried Slot protocol. Never guess a Slot name,
  key, selector, props shape, or replacement behavior.
- `ctx` belongs to the plugin `apply` world. Components receive plain data and
  callbacks through declared props or inject surfaces; components never see
  `ctx` and never reach into Services or Cordis contexts.
- Never copy, stringify, recursively inspect, or retain whole live DSH runtime
  objects. Extract only the scalar fields the feature needs.
- Use JSON-only, lossless arguments and results across the Host/Client boundary.
  Never pass Services, Contexts, React elements, functions, or other live
  runtime objects across it.

## Codebase-specific rules

- `src/client/locale-extension.ts` is the only module allowed to contact
  locale internals (`snapshot`, `publish`, and `adopt`). Keep its runtime
  capability check and its disposer in place when touching that code.
- Dictionary edits in `src/client/dictionaries.ts` must preserve every
  placeholder verbatim, such as `{name}`, and must pass `pnpm typecheck`.
  That typecheck is also the compile-time dictionary-drift check after a DSH
  upgrade.
- Never add a value import of an `@deepseek-ai/*` package. Use `import type`
  only; a value import breaks the zero-`require` purity gate.
- `lib/` is generated by the build; never edit generated JavaScript or
  declarations directly.
- The build gates in `scripts/build.mjs` are load-bearing: preserve the
  module-loader envelope, zero-`require` check, module-syntax check, and
  `apply`/`inject` export checks.
- Keep Japanese persistence in the plugin's `dsh-locale-ja:preference`
  storage key, never in the Host `locale` settings scope, and keep the
  Japanese font in the plugin-owned style tag only.

## Development strategy

### Performance

- Keep activation and locale switching bounded: no polling, retry loops, or
  repeated full-tree scans.
- Avoid needless allocation or serialization, including unnecessary cloning or
  reconstruction of locale snapshots and dictionaries.
- Use system fonts only; do not fetch web fonts or add network work for this
  feature.
- Keep the browser bundle free of `require()` calls and add no dependency the
  feature does not need.

### Simplicity

- Make the smallest coherent change that preserves the standard package
  contract.
- Reuse the platform locale Service and lifecycle; keep local types minimal and
  add no speculative abstraction.
- Fix root causes instead of suppressing diagnostics or special-casing inputs.

### Side-effect control

- Mutate only inside the plugin lifecycle, normally through `ctx.effect()`.
- Own a disposer for everything the plugin registers or mutates, including
  dictionary registrations, locale overrides, subscriptions, style tags, and
  persistence hooks.
- Restore prior behavior on every teardown path, including partial setup and
  failed updates.
- Do not create global DOM or process state beyond the plugin's own style tag
  and storage key.

## Change workflow

1. Read `ARCHITECTURE.md`, the relevant ADR, and the current implementation
   before editing. For a DSH contract change, inspect the real
   runtime/provider contract first.
2. Keep the package layout, `exports`, `dsh.client` manifest,
   `dsh.bundle.patch`, and the declaration output synchronized.
3. Keep dictionary keys aligned with the shipped declarations, preserve
   placeholders exactly, and run `pnpm typecheck` after dictionary or DSH
   version changes.
4. Review the diff for accidental value imports, guessed Slot contracts,
   broadened side effects, missing disposers, and edits to generated `lib/`.
5. Run the narrowest relevant validation, then finish with:

   ```bash
   mise run check
   ```
